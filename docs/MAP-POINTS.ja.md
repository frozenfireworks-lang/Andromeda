# Navigationの地図による地点選択

## 使い方
1. 既存のAndromeda Navigation画面を開きます。
2. 「Start Point（出発点）」の「地図から選択」を押します。
3. 専用地図をタップしてピンを置き、「この地点を選択」で確定します。
4. 「Destination（目的地）」も同じ手順で指定します。
5. 2点が決まるとMapKitの経路検索が自動実行されます。Navigation画面内の地図で経路を確認し、必要なら候補を切り替えます。
6. 既存の移動モード・速度倍率で速度を指定します。経路確認後に「Start Route Simulation」を押すと初めて位置が移動します。

住所検索、GPX読み込み、移動モード、速度倍率、一時停止・停止は既存の機能を流用しています。新しい独立したナビゲーション画面は追加していません。
速度は既存UIどおり「移動モードの基準速度×倍率」です。自由入力のkm/h欄は追加していません。
経路取得には通信とMapKitの対応地域が必要です。取得できない場合はエラーを表示し、開始できません。

## GPS誤操作の保護
- 地点選択地図はローカルの候補座標だけを持ち、LocSimManagerやRouteSimulatorを参照しません。
- 「この地点を選択」は出発点/目的地の設定だけを行い、GPSを変更しません。
- キャンセルは候補を破棄します。既存のシミュレーションを開始・停止する処理も呼びません。
- 経路プレビューの地図は地点タップを受け付けません。
- Navigation表示中は背面の通常地図のヒット判定とGPS変更ハンドラーを両方無効にしています。
- GPS反映は確認済み経路の明示的な開始操作に限定します。既に実行中だった位置シミュレーションそのものを、地点選択開始時にリセットすることはありません。
- 地点・モード変更で古い非同期リクエストを無効化し、遅れて返った旧経路を採用しません。
- 日本のWGS-84座標保持は前回の修正を維持し、地図で選んだ座標をここで追加変換しません。

## 検証
- `python3 scripts/test-navigation-safety.py`: GPS操作からの分離、背面地図の保護、プレビューのタップ無効化、明示的開始、キャンセル時の保護を検査するソース構造チェック5件。
- `swift test`: 既存の座標・GPX・速度テスト12件に、古い応答とキャンセル済み応答の排除2件を追加。
- GitHub ActionsでiOSアプリ・RootHelperをビルドし、entitlementsを検証してTIPAを生成。

ソース構造テストは画面操作テストの代用ではありません。実機では、選択・確定・キャンセル・経路候補切替・速度変更の各操作で開始前のGPSが変わらず、開始を押した後だけ指定経路を移動することを確認してください。
